# Agno-Go 架构通俗讲解（给非技术读者/考核演示用）

> 目的：用生活类比解释抽象、封装、软件架构，以及 Agno-Go v2 的分层设计。
> 配套：技术终稿见 `docs/design/go-agent-framework-design.md`。

---

## 1. 三个基础概念（生活类比）

### 抽象 —— 把复杂的藏起来，只留简单的"把手"

- 开车：踩油门/刹车/打方向盘，不需要懂发动机。
- 代码：`Model` 接口只有 `Invoke`（问一次）/ `Stream`（流式问）两个方法，屏蔽 17 家 LLM 的 API 差异。业务代码只面对这两个方法，换模型不用改代码。

### 封装 —— 内部随便改，外部不受影响

- 药丸：外壳不变，内部配方换了，吃法一样。
- 代码：`Agent` 内部怎么循环、怎么组织消息，外部只调 `Run()`。内部重构 10 次，调用方代码依然能编译运行。

### 软件架构 —— 大楼的设计图

- 餐厅：后厨（切菜/炒菜/传菜）与前台（点单/收银）分工明确——这就是架构。混在一起就乱。
- 代码：分层设计。每层只做一件事，层与层之间通过"接口"（约定好的门）通信。

## 2. Agno-Go v2 的三层架构

```
┌───────────────────────────────────────────────┐
│  第 3 层 门面层：Agent / Team / Workflow        │
│  "服务员" —— 你写代码主要用这层                  │
│  接待请求、组装工具、返回结果                     │
├───────────────────────────────────────────────┤
│  第 2 层 引擎层：runner 执行引擎                 │
│  "后厨总管" —— 框架内部，你不用管                │
│  循环调用模型、判断何时停、执行工具、处理流式      │
├───────────────────────────────────────────────┤
│  第 1 层 适配层：models.Provider                │
│  "供应商" —— 换模型只动这层                     │
│  对接 OpenAI / Anthropic / DeepSeek / Ollama…  │
└───────────────────────────────────────────────┘
```

### 为什么这么分？（三个实际好处）

1. **换模型不动业务代码**：第 1 层隔离了 17 家 LLM 的差异。今天用 GPT-4，明天换 Claude，业务代码零改动。
2. **引擎坏了只修第 2 层**：循环逻辑、停止条件、工具调度集中在一处，修 bug 改一处即可。
3. **不重复造轮子**：单 Agent、Team（多智能体）、Workflow（工作流）共用一个引擎。Python agno 就是栽在这——Team 把 Agent 的引擎复制了一份（8963 行重复代码），修一个 bug 要改两处。

### 每层的职责一句话

| 层 | 名字 | 职责 | 类比 |
|----|------|------|------|
| 3 | Agent/Team/Workflow | 组装与编排 | 服务员 |
| 2 | runner | 工具循环与停止控制 | 后厨总管 |
| 1 | models.Provider | 对接各家 LLM | 供应商 |

## 3. 为什么设计成这样（对比教训）

| 设计选择 | 为什么 | 反面教材 |
|---------|--------|---------|
| 引擎独立成层 | 一处循环，三处复用 | agno 循环藏在 Model 层，重复 4 份 |
| Agent 只做编排 | 保持简单，职责单一 | agno Agent 115 个参数（God Object） |
| 工具类型安全 | 编译期发现错误，不靠运行时猜 | 旧代码 map[string]interface{} 参数 |
| 技能渐进式披露 | 技能多了不费 token | 全量注入 instructions |

---

## 4. 考核演示话术（30 秒版）

"我们的框架分三层：门面层（Agent/Team/Workflow，开发者用）、引擎层（统一的执行循环）、适配层（对接各家大模型）。好处是：换模型不用改代码、修 bug 只改一处、单 Agent 和多 Agent 共用同一引擎。相比之下，Python 的 agno 框架把循环逻辑在模型层复制了四份，Agent 有 115 个构造参数——这就是我们重新设计的动机。"

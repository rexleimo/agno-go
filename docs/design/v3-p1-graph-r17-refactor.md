## 3. 四条存活的解释与登记的缺口（契约 completionCriteria 第 6 项：不静默放宽）

1. **ο 是等价变异，不是漏检。** 互换后取消与预算两条判据仍都在 `spawn` 之前问到，同一次循环迭代里
   谁都还没把激活交给节点，因此不存在能被观察到的差别。它给出的结论是：该行牙齿的位置是「spawn 之前」，
   不是「预算之前」。已按这个措辞改写注释（第 1 节第 2 条）。
2. **χ / ρ 存活 = 契约 D2 的牙齿归属需要更正。** 契约 D2.teethMutant 写着「ν 取到 item.err 后原样
   return（不看 ctx）→ D2 红」；实测在保留派发守卫的前提下，消费者会先在 `dispatch` 的循环头交出取消、
   根本走不到队列项分支，所以这一条守卫**没有任何单条变异能单独把它判红**。它仍然判得出红是 κ 的组成部分
   （τ 单独拿掉派发守卫时 D2 判绿 ⇒ κ 的 D2 判红归因到队列项侧那条守卫），并且 `raceAssertionForm.greenMustBeDeterministic`
   把「消费者已经从 queue 取走了结果」这一确定时刻的咨询指定为修复点，所以**实现保留、行保留、断言不放宽**。
   缺的那一块是能落到「消费者 parked 在 select 且队列里已有一条业务错误」这一窗口的夹具
   （形如 `entry → {gate 放行的失败节点, 永不返回的阻塞节点}`，`close(gate)` 与 `cancel()` 由两个 goroutine 同时发出）。
   本轮**没有新增这个夹具**：新增覆盖属 RED 阶段动作，在 REFACTOR 里做会越出当前 Command 的阶段边界。
   → 登记为待办，挂 review：`R17-GAP-1（D2 队列项侧守卫缺独立杀手，需 parked-window 夹具）`。
   **本条已被第 7 节的补跑部分推翻**：契约逐字点名的 λ「用快照 ctx 值」形态（`L_snap`）单独就能把 D2
   判红（一次实跑即命中第 17/31/32/37… 轮），所以 D2 并非没有独立杀手，缺的只是「把守卫整个删掉」这一种
   写坏法 —— 而那一条在派发侧守卫还在时确实不可达。R17-GAP-1 收窄为「χ（整条删除）不可达」，不再是「D2 无牙齿」。
3. **π 没有 fire D5 的 `:419`，说明那一行的牙齿尚未建立。** 该断言要成立，需要取消之后消费者再次进入
   `dispatch` 并把积压放出去；而 D5 第一段夹具里没有任何节点在取消时向 queue 投递，消费者从 select 的
   `ctx.Done` 分支直接返回，不再回到 `dispatch`。换成能进入派发窗口的形状（D5 第二段）则这条断言本身不成立：
   `started` 是在节点体里登记的，spawn 之后到登记之前有 goroutine 启动偏差，正确实现也会偶然多算 —— 那会把
   一条真判据写成竞态容差，属契约 forbiddenShortcuts。→ 登记为待办，挂 review：
   `R17-GAP-2（D5:419「取消停在派发之前」无任何变异可达；与 R17-UNADJ-1 同一裁决面）`。
   该行**保留**（契约 D5.teethMutant σ 指名它，删行等于放宽），λ / υ 两行已证明 D5 整体不是空行。
4. 承 GREEN 的预告：**D3 没有任何 solo 杀手**（υ 命中了 D4/D5 却没命中 D3，派发守卫在时它走不到差别点），

   （有积压时不咨询）→ D5 红」。按该形态逐字写的 `R_empty`（第 7 节）实跑判红的是 **D1**，D5 判绿。
   机制清楚：有积压且不咨询时，消费者一路排空到撞上预算判据才交出错误，而那正是 D1 钉的形状。
   → 该行仍被杀死（不是漏检），只是杀手归属要从 D5 改到 D1；已并入回写清单。
6. **σ 存活 ⇒ D5 的「取消停在派发之前」这一行确认无任何杀手，R17-GAP-2 由推断升级为实测。**
   此前只记了复合形态 π（拿掉派发守卫 + 绕过上限）判红 D1、没判红 D5:419，还留着「单独绕过上限也许能被
   D5 接住」这一线可能；`mutants7.out.txt` 在最终字节上单跑 σ：`exit 0`，6 行 Test 全绿、无 DATA RACE、

   被放行**的形状，而那要先解掉 D5:419 的登记竞态（`started` 在节点体里登记，spawn 与登记之间有 goroutine
   启动偏差）：要么把「节点开始运行」变成公共面上可判定的信号（现有 API 做不到，见 `S17-SPEC-2`），
   要么接受该行的牙齿由 D1/D4/D5 的整体形状间接担保。→ 挂 review，**不删该行、不放宽 σ 的目标形状**；
   契约 D5.teethMutant 的归属更正为「λ（`:410` 阀内未返回）+ υ（`:413`/`:416` 交出 Result）」，σ 移入
